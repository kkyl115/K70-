# 技术候选核对：用途、现有证据与实施条件

> 2026-10-31 更新：下文原 config 结论为历史记录。新 ZIP 已证明 BBG、KPM、LZ4KD 编入，但默认网络为 Cubic；NoActive 配套 KPM 已由用户确认。以[新基线核验](当前内核核验-20261031.md)为当前事实入口。BBG 独立对象编译也已通过，仍未做 LSM 运行测试。

本报告对应 Redmi K70 / vermeer / android13-5.15，2026-10-28。结论来自用户上传 config、已取回的 ACK 源码和锁定的上游源文件；不把项目宣传、配置打开或补丁可应用当成真机成功。当前完整 Image 构建、当前 vendor ABI 和启动验证尚未通过。

## 用户提出的技术

| 技术 | 实际用途 | 本项目证据及决定 |
|---|---|---|
| BBG / Baseband Guard | 在运行它的 Android 内核中，用 LSM 拦截被策略判为不可信进程的部分关键块设备写入与破坏性 ioctl，降低恶意 Root 脚本误写风险 | 已取得并审查真实源码；当前上传 config 未记录 BBG。列为安全候选，未集成、未编译、未实机测试 |
| BBRv3 | 根据网络带宽/时延模型控制 TCP 发送节奏，在某些链路改善吞吐、排队时延与丢包恢复 | 上传 config 已有 BBR3，默认字符串 bbr3，fq 也启用；缺此第三方回移补丁的准确来源和运行时证据。优先还原与验证，禁止重复叠加 |
| NTSync | 提供 Windows NT 的 mutex/semaphore/event 等同步语义，给使用该接口的 Wine 类兼容层减少同步开销 | 已锁定 Linux v6.14 原实现及 selftest；驱动未经语义修改，在历史 ACK 5.15 的独立准备目录通过对象编译。尚未完成模块链接、后续修复审查或并发测试。是 Winlator/Wine 场景候选，不是所有 Android 原生游戏或模拟器的加速器 |
| WireGuard | 内核 VPN 数据通道；可用于连接自家服务器、访问内网或加密隧道 | 上传 config 已 CONFIG_WIREGUARD=y，先保留与验证。仍需要客户端、密钥、对端和路由/DNS 配置；内核选项本身不会提供 VPN 服务 |
| ZRAM + 压缩算法 | 用 CPU 压缩换取更高的 RAM 有效容量，在内存压力下延缓换页/杀后台 | 已有 ZRAM=m、zsmalloc=m，编译默认 lzo-rle；LZ4/ZSTD 代码存在。实际已初始化算法、模块 CRC、压缩比和耗电必须另测 |
| DroidSpaces | 用 namespace/cgroup 等运行 Linux 发行版用户空间，共享手机内核；原生 ARM64 工作负载不需要 CPU 指令翻译 | 当前配置缺少 SYSVIPC、PID namespace、devtmpfs 等必要项；存在 GKI ABI 与 SUSFS 挂载可见性冲突。保留独立容器实验配置，暂不并入日用候选 |

来源：[BBG](https://github.com/vc-teahouse/Baseband-guard)、[Google BBRv3](https://github.com/google/bbr/blob/v3/README.md)、[NTSync 内核接口](https://docs.kernel.org/userspace-api/ntsync.html)、[WireGuard](https://www.wireguard.com/quickstart/)、[ZRAM](https://docs.kernel.org/admin-guide/blockdev/zram.html)。DroidSpaces 依赖与冲突参见 [GKI 配置说明](https://www.droidspaces.org/docs/kernel-configuration.html)、[安装说明](https://www.droidspaces.org/docs/installation-android.html)。这些资料的最新功能不代表已存在于本机 5.15。

## BBG 源码审查所得的适配问题

审查版本 `vc-teahouse/Baseband-guard@028ff7fd509e2104596da7cc1ef8e6ce2a0c9082`，日期 2026-10-26，GPL-2.0。源码证据在 `evidence/upstream-research/candidates/bbg/`。

1. `baseband_guard.c` 注册 `file_permission`、`file_ioctl`、`inode_setattr` 与凭据相关 LSM hooks，按块设备号匹配。它不是 Bootloader 功能，也不能覆盖另一套 Recovery 内核、Fastboot、已取得任意内核执行权的攻击或所有存储硬件故障。
2. `tracing/tracing.c` 追踪 su/ksu/magisk 等 SELinux 域派生的不可信凭据；`current_process_trusted()` 可以提前放行。不能把它描述成“任何进程都写不了基带”的绝对保护。
3. 默认 `BBG_BLOCK_BOOT=n`，allowlist 包含 boot/init_boot/vendor_boot；dtbo、vbmeta、misc 也在名单中。因此默认策略并不满足本工程“保护已验证 A 槽”的全部要求。需从实际分区设备号、槽位与授权写入者建立设备专属规则。
4. `blkdev_helper.c` 从 `saved_command_line` 读槽位后缀，没取到时允许名单匹配两槽。Android bootconfig 的实际信息来源必须纳入评估，不能假定 cmdline 一定包含槽位。
5. 许可设备缓存的 hash 查找/插入没有在该文件中展示显式同步，需要并发访问与生命周期审查。它记录 argv 的日志路径也需限流、敏感字段最小化；不应全量关闭安全日志。
6. OTA/update_engine、modem 固件维护、Root 模块与 BootGuard 恢复流程的合法写入必须逐项验收。仅按进程名放行不充分。测试必须使用隔离 VM/临时 loop 设备，不对手机真实关键分区发出“试试看会不会被拦截”的写入。

建议新增的是经过验证的设备策略、可追溯审计与恢复协同，复用现有 LSM 实现前先完成上述审查。不另造未经测试的“防砖算法”。

## 网络与模拟器的收益边界

BBR 控制发送端 TCP。手机修改默认算法，不能强制远端下载服务器改算法；多数 UDP 游戏包与用户态 QUIC 不会直接改走 Linux TCP BBR。Google 的 v3 源码注册名是 bbr；上传配置中的 bbr3 名称提示还有第三方适配，不能仅靠名字确认代码版本。测试须分别观察上传/下载、RTT 尾部、重传、公平性和功耗，保留 Cubic 对照及回滚。

NTSync 需要内核驱动、/dev/ntsync 的正确访问控制，以及确实调用它的 Wine 构建。ARM64 上运行 x86/x64 软件通常仍需要相应翻译层；NTSync 不负责指令翻译或 GPU 加速。验收应包含上游 selftests 的 wait-any/wait-all、超时、信号中断、事件重置和 mutex abandoned 语义，再比较同版本 Wine/游戏的帧时间和 CPU 开销。仅驱动编译成功或设备节点存在都不算启用成功。

## DroidSpaces 的可行范围

它是容器运行时，不提供第二个独立 Linux 内核。相同 ISA 的用户程序原生执行可以避免传统模拟/ptrace 路径的一部分开销，但文件系统、网络、图形桥接、资源竞争和温控仍有成本；“零性能损失”需要具体工作负载证据，不能直接用于本机承诺。

本机 config：SYSVIPC=n、POSIX_MQUEUE=n、PID_NS=n、DEVTMPFS=n；IPC_NS 没有记录为开启。NET_NS、VETH、BRIDGE、OVERLAY_FS 已存在。USER_NS、CGROUP_PIDS 也未开启，但应按所选功能核对，不能把所有推荐项一口气打开。

上游提供 SYSVIPC 的不同 ANDROID_KABI padding 槽位补丁。本工程不采用“刷不启动就换另一个 padding”的试错方式：先审查当前 task_struct 的保留槽是否已被 Root/厂商补丁使用，再比较类型布局、符号 CRC 和真实厂商模块。CPU bandwidth/pids 等选项需单独 ABI 检查，不能套用 IPC padding 补丁的兼容结论。

上游还明确不支持 SUSFS 环境，并提示全进程隐藏挂载会阻止容器启动。应将容器实验和全局挂载隐藏作为冲突组合记录，先验证准确版本与设置；不能承诺全功能同时开启。SELinux 必须继续 enforcing，仅提供经审查的最小权限，不能靠全局 permissive 运行。

## 其他有依据的新方向

| 方向 | 用途及实现位置 | 当前状态和决定 |
|---|---|---|
| pstore/ramoops 启动故障证据链 | 在 DT 预留内存及 pstore 驱动支持下，尽可能保留 panic/重启日志，供 BootGuard 下次启动只读归档并关联镜像哈希 | 上传 config 已 PSTORE_RAM=y。需核对设备树预留区域与实际 pstore 文件；不修改保留地址，不承诺捕获所有早期失败或断电 |
| DAMON 观察与限额回收 | 按内存访问冷热度观察，再研究轻压力/空闲时的有限额回收，目标是减少前台突发直接回收 | 上传 config 已 DAMON_PADDR、DAMON_RECLAIM=y。先读取运行状态；不能再称新移植。与 MGLRU/LMKD 协同做对照，避免重复回收和压缩 CPU 开销 |
| futex_waitv / fsync 兼容路径 | 支持一次等待多个 futex，为采用相应实现的兼容层提供另一条同步路径 | 标准接口见 Linux 5.16 文档；历史 ACK 5.15 syscall 表未检出该接口，当前第三方补丁待核。与 NTSync 按用户态后端选择，不能把两个名称的收益相加 |
| VAS 的观测先行接入 | 记录 wakeup-to-run、迁移次数、CPU MIDR/容量、thermal pressure 与 cpufreq policy；用这些数据校准已有 C 原型 | 主机原型、模拟回放、目标 5.15 对象编译与主机静态检查均通过；无真实调度 hook 接入及性能结论。优先复用 WALT/EAS/uclamp，不替换整个调度器 |
| 以帧时间和压力为约束的调优 | 用 Perfetto/tracepoints 和 PSI，把 p95/p99 帧时间、任务等待、内存停顿、功耗作为三种策略的验收条件 | 测量/分析框架方向，尚需真实数据。保持 thermal/cpuidle 原有约束，不把频率锁最大作为优化 |

参考：[pstore/ramoops](https://docs.kernel.org/admin-guide/ramoops.html)、[DAMON reclaim](https://www.kernel.org/doc/html/latest/admin-guide/mm/damon/reclaim.html)、[futex_waitv](https://docs.kernel.org/5.16/userspace-api/futex2.html)、[PSI](https://docs.kernel.org/accounting/psi.html)、[EAS](https://docs.kernel.org/scheduler/sched-energy.html)。

SELinux 策略伪装改变可见信息，日志静默削弱问题追溯，二者都不能直接算成安全增强。保留真实 enforcing、最小权限和必要审计，日志采用限流/脱敏；不伪造安全状态。
