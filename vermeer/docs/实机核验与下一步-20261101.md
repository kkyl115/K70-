### 短时压力观测

新增固定 4 次采样、每次间隔 10 秒的只读工具。按 /proc/uptime 中点计算，三个窗口合计约 31.57 秒；每次顺序读取约 0.42–0.56 秒，因此数值是近似值，不是同步 trace。

| 每个窗口的范围 | 实测 |
|---|---|
| CPU PSI some | 13.00–15.14% |
| 内存 PSI some / full | 0.13–0.78% / 0.12–0.77% |
| I/O PSI some / full | 1.09–4.68% / 0.77–4.32% |
| swap 换入 / 换出 | 0.91–6.56 / 0.02–1.31 MiB/s，按页面逻辑字节计算，不是 UFS 吞吐 |
| 电池 | Charging，41.7–41.9°C |

PSI 是资源停顿时间比例，不是 CPU 利用率或应用帧延迟。此时前台活动、模块行为、充电和热状态没有受控；只能确认存在换页与等待，不能认定发生持续严重内存抖动，更不能给出优化百分比。三个窗口中后两个有较高 I/O full，值得在复现场景里核对来源，但不能直接归因于 BFQ/CPQ。

## 下一步顺序

1. **MGLRU 单变量试验候选。** 不需要再安装模块。先做相同应用切回顺序的基线，在温度和充电状态可比时，再考虑只启用主开关。目标是比较切回时的回收停顿、refault、LMKD 杀进程和通知；不是只比较“剩余内存”。
2. **保留 LZ4KD 与 16 GiB 容量，先测成本。** 当前压缩效果有实测依据，但没有算法速度/能耗比较。在线重建 ZRAM 会涉及 swapoff，暂不纳入首轮。
3. **NoActive 白名单与解冻链路。** 保留现有 ReKernel-X，重点检查通讯、导航、音乐和分享调用的通知/解冻延迟。采集本轮未读取应用清单或改规则；无需追加同类 KPM。
4. **VAS 先接观测，再调 WALT/任务放置。** 升降频限速已为 0，继续追求更低没有意义；这不等于硬件响应没有延迟。A715 与 A710 仍共享 policy3，不能分别设置两套频率。结合真实线程 runnable 延迟、迁移和帧时间后再决定阈值。
5. **按实际用途选新增功能。** 使用支持相应接口的 Wine/Winlator 才优先 NTSync；需要 Linux 容器才开 DroidSpaces 独立分支；BBRv3 需 5.15 回移及网络对照。WireGuard 已有，不必再集成。DAMON、ZRAM writeback 和额外冻结器不与第一轮 MGLRU 同时启用。

### 可审阅的 MGLRU 试验边界（未执行）

- 候选节点：/sys/kernel/mm/lru_gen/enabled；本轮原值 0x0000，候选值 0x0001，只启用主算法。min_ttl_ms 保持 0，不叠加其它回收/调度变化。
- 参数单位是位掩码。已核对 ACK 362d545d31a5659546d5546c7ae206f745e98c3e 的 mm/vmscan.c:store_enabled、include/linux/mmzone.h，bit0 为 LRU_GEN_CORE。它只是第三方内核的参考基底，不能替代完整补丁审计；不声称 0x1 是最优策略。
- 当前工程只有只读执行器，没有自动写入后端。机主最初要求实机写入单独确认，因此本报告不是执行授权。获准后仍须重新核对设备、Root、配置、原值和温度；若基线变化则重新评估。
- A/B 时固定亮度、刷新率、网络、模块配置及充电条件，温度落在可比范围。充电发热下采集的数据不能作为续航结论。
- 若出现异常重载、ANR、通知缺失或持续压力升高，停止试验并恢复事前记录的原掩码，读回确认。不开机持久化，不以“重启会恢复”作为唯一回滚保证；ADB 断连时不能承诺自动恢复。
- ABBA 多轮对照必须包含实际切回时间/帧时间和重要通知验证。仅凭本轮 PSI 或主观手感不能决定正式合并。
