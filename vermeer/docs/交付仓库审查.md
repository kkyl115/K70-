## 与本设备质量门禁的差距

- `.github/workflows/scripts/config.py` 默认从移动分支获取 Root/SUSFS/辅助 patch；SUSFS 版本探测关闭 TLS 证书校验，探测失败回退到固定显示字符串。显示版本不能当成源码身份。
- `kernel_builder.py` 多处 clone/checkout/patch 使用 `check=False`，SUSFS `--fuzz=3`。补丁失败可能继续到后续步骤，本工程不沿用这条发布路径。
- `CONFIG_KPM=y` 出现在基础 config 片段；是否真正打二进制补丁另受选项控制。配置与成品处理必须核对，防止含糊状态或重复 patch。
- KPM patcher 从移动 URL 下载并直接执行，失败允许继续。缺少精确源码/工具哈希与输入输出身份门禁。
- BBR 选项为 `CONFIG_TCP_CONG_BBR` / `CONFIG_DEFAULT_BBR`，不能证明实现了用户上传配置中的 BBR3。
- 默认启用创建 Release 和 Telegram 通知。本工程独立 workflow 不发送消息、不自动发布刷机包、不触碰手机。
- 通用 AnyKernel/boot 打包没有当前 vermeer 运行镜像、完整厂商模块 CRC 和已验证 BootControl 证据，不能作为设备适配结论。

这些是对具体版本的代码审查，不是对仓库所有产物的启动结果判断。本次没有执行上述上游安装脚本或二进制 patcher。
