交叉印证：

**结论：不需要再给 init_boot 打 KSU 补丁。任务书里「打补丁」环节应改判为「验证」，直接用 `magiskboot` 校验现网镜像即可。**

若机构实，意味着 `CONFIG_MODVERSIONS=y` 下的模块加载校验被定制放宽，或 vendor_dlkm 是旧固件遗留。

**三方互不相同。**
- `init_boot_a` 线上 ≠ 12:42 备份 → 12:42 之后 init_boot 被写过（KSU 再次打补丁）

**判定**：`A_backup_20261027_124239` **不能当作"当前状态回滚点"**；它至多是某个中间态。
`/data/adb/ksu/ksu_backup_6555eec9…`（09-06）才是更可能是"首次 root 前的原厂 init_boot"。

**行动**：重新冻结两份基线 —— ①当前线上真值 ②候选原厂值，并用 `magiskboot unpack` 逐项比对内容，而非只比哈希。

## 四、MGLRU：可以运行时开启（不需要重编内核）

```
CONFIG_LRU_GEN=y
# CONFIG_LRU_GEN_ENABLED is not set     ← 默认关
# CONFIG_LRU_GEN_STATS is not set

/sys/kernel/mm/lru_gen/enabled     -rw-r--r-- root root   值 0x0000
/sys/kernel/mm/lru_gen/min_ttl_ms  -rw-r--r-- root root   值 0
```

**文件存在、root 可写、当前关闭。** → 这是本机唯一"零编译、可逆、立刻生效"的内核级优化点。
启用后写入位掩码，内核会按支持的位回读（可写入后立即读回确认被接受的真实位）。
回滚：写回 `0x0000`。

风险：本机内存已紧张（见第六节），切换回收器瞬间可能引起一次内存抖动。**需你确认后再执行。**

## 五、ZRAM：可优化，但**禁止热切换算法**

```
disksize          17179869184 (16 GiB)
comp_algorithm    lzo [lzo-rle] lz4 zstd      ← 当前 lzo-rle，zstd/lz4 可用
max_comp_streams  8
backing_dev       /dev/block/dm-51
CONFIG_ZRAM_WRITEBACK          is not set     ← 无 writeback
CONFIG_ZRAM_MEMORY_TRACKING    is not set     ← 无 zram 统计
```

- 已用 swap **6858668 kB ≈ 6.5 GiB**（16383 MiB 中）
- ⚠️ 换算法必须 `swapoff` + `reset`。此刻换出 6.5 GiB 回物理内存 = **必然 OOM/假死**。
- **只能重启时生效**（init 脚本 / 模块），不能在本会话热切。

可选方向：`lz4`（解压快、CPU 低，低压场景更优）vs `zstd`（压缩率高，但 6.5 GiB 热数据上 CPU 代价明显）。
本机 15 GiB RAM + 6.5 GiB 已换出 → 属**高压场景**，倾向 `lz4`，但必须用同条件跑分验证，不凭经验下结论。
