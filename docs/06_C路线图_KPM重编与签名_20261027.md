## 一、签名验证能否「关掉」—— 实测结论 [事实]

### 1.1 内核配置（来自 evidence/root_*/kernel_config.txt）

| 配置项 | 值 | 说明 |
|---|---|---|
| CONFIG_MODULE_SIG | y | 模块签名机制开启 |
| CONFIG_MODULE_SIG_FORMAT | y | — |
| CONFIG_MODULE_SIG_FORCE | **not set** | **不强制**校验签名（已是最宽松） |
| CONFIG_MODULE_SIG_PROTECT | y | Android 特有保护，可能拒载校验失败模块 |
| CONFIG_MODULE_SIG_ALL | y | 自动签名全部模块 |
| CONFIG_MODULE_SIG_HASH | "sha1" | — |
| CONFIG_MODULE_SIG_KEY | certs/signing_key.pem | 编译期内置密钥 |
| CONFIG_MODULE_SIG_KEY_TYPE_RSA | y | — |

### 1.2 运行时 sysctl [事实]

- `/proc/sys/kernel/modules_disabled = 0`
- `/proc/sys/kernel/` 下**没有任何**「关闭签名验证」的 sysctl 项
- 相关项仅：`modules_disabled`、`max_lock_depth`、`perf_event_mlock_kb`、`print-fatal-signals`、`softlockup_*`

### 1.3 结论

1. `MODULE_SIG_*` 全部是**编译期** Kconfig，运行时**无法**通过 sysctl 开关。[事实]
2. `MODULE_SIG_FORCE` 本就未开 → 已是「不强制验签」状态；真正的风险点是 `MODULE_SIG_PROTECT=y`。[事实]
3. 要关掉 `MODULE_SIG_PROTECT` 只能**重编内核**改 `.config`。[推断]
4. `modules_disabled=0` 只表示「当前允许加载模块」，**不等于**「签名校验已关闭」。[事实]

## 二、「签名伪装」澄清 [事实+推断]

- **签名伪装（signature spoofing）** 是 **Android framework 层**补丁，改 `services.jar`/framework，用于 microG 伪装 Google 签名。**与内核重编无关**。[事实]
- 本机实测：`/data/adb/lspd` 不存在、`getprop` 无 spoof/signature、无 microG/FakeGApps 痕迹。[事实]
- 结论：若目标是「签名伪装」，应走 LSPosed/microG/FakeGApps 路线，**不属于**内核重编路线图。[推断]

## 三、KPM 现状与路线 [事实]

### 3.1 实测证据（三条独立）

1. 内核配置：**无 KPM 相关项**（无 CONFIG_KPM 或同类）；且 `CONFIG_KSU_MANUAL_HOOK` 与 `CONFIG_KSU_TRACEPOINT_HOOK` 均未开启。
2. `/proc/kallsyms` 中 8 个 "kpm" 命中符号全部是 `clkpm_*` / `pcie_set_clkpm`（时钟电源管理），与 Kernel Patch Module 无关。
3. `/data/adb/ksud` 二进制内 "kpm" 字样 = 0 个。

### 3.2 结论

- KPM 在本机是 **内核侧 + userspace 侧双缺失**，不是差一个开关。[事实]
- 启用 KPM 属于 **重编级**：需 SukiSU 内核源码带 `kpm/` + 换带 KPM 的 ksud/管理器 + 重刷 boot。[推断]

## 四、重编通用路线（含 KPM）— 前置条件清单

### 4.1 源码获取 [未验证]

- [ ] 获取与本机 `5.15.178` 对齐的 SukiSU-Ultra 内核源码
- [ ] 确认源码 tree 内 `kpm/`、`susfs/`、BBRv3、各 TCP CC 补丁是否已包含
- [ ] 获取小米官方 `Module.symvers`（或从现网模块反推）

### 4.2 工具链 [事实]

- 必须 `clang 14.0.7 (r450784e) + LLD 14.0.7`，且 **x86_64 Linux**
- **Termux aarch64 无法编译 Android 内核**（架构/物理限制，非权限问题）

### 4.3 符号 CRC 校验（关键门槛）[事实]

- `CONFIG_MODVERSIONS=y` + `CONFIG_CFI_CLANG=y`（**未开 permissive**）
- 293 个 vendor `.ko`（vermagic=5.15.78）+ 113 个 boot 内嵌 GKI 模块 = 406 行已加载模块
- 新内核导出符号 CRC 必须与 293 个 vendor 模块一致，否则相机/WiFi/音频全废不开机

### 4.4 A/B 回滚 [事实]

- 现 slot = `_a`；boot_a 哈希 `e0545946c35f...`
- 回滚手段：fastboot 刷回原 boot_a / 或切槽

## 六、结论摘要

| 需求 | 类型 | 可行性 |
|---|---|---|
| KPM | 重编 | 双缺失，需源码+工具链+重刷 |
| 关 MODULE_SIG_PROTECT | 重编 | 运行时不可关 |
| 签名伪装（signature spoofing） | framework 层 | 与内核无关，另开 LSPosed/microG 线 |
| MGLRU 0x0003 | 已生效 | 可保持，写 0 回滚 |
