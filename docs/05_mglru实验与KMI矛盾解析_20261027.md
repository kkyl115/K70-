# 05 — MGLRU 实测 + KMI/vermagic 矛盾解析（2026-10-27）

> 状态标注：**[事实]** 工具实测 / **[推断]** 基于事实的推理 / **[未确认]** 待进一步验证

## A. MGLRU 实验（零编译、可逆）

### A1. 开关写入结果 [事实]
- 写入 `echo 0x0007 > /sys/kernel/mm/lru_gen/enabled` → 读回 `0x0003`
- 即：bit0(基础 LRU_GEN) + bit1(MM_WALK) 生效；**bit2(0x0004, NONLEAF_YOUNG) 写不进去**
- 原因 [事实]：`kernel_config.txt` 仅 `CONFIG_LRU_GEN=y`，无 `LRU_GEN_NONLEAF_YOUNG` / `LRU_GEN_STATS` / `LRU_GEN_ENABLED`
- **结论 [事实]：本机 MGLRU 上限 = 0x0003，bit2 特性未编入内核，需重编才有**

### A2. 120 秒前后对比 [事实]
| 指标 | A0 基线 | A3 +120s | 方向 |
|---|---|---|---|
| lru_gen/enabled | 0x0000 | 0x0003 | 开启 |
| MemFree | 107 MB | 657 MB | **+550 MB** |
| MemAvailable | 5332 MB | 5572 MB | +240 MB |
| nr_free_pages | 26434 | 164043 | **6.2×** |
| nr_inactive_anon | 614247 | 295506 | -52% |
| SwapFree | 9259 MB | 8609 MB | -650 MB（换出更多）|
| pgmajfault | 981319 | 1064989 | +8.4% |
| zram 压缩数据 | 7697 MB | 8363 MB | +666 MB |
| PSI cpu some avg10 | 15.04 | 17.69 | ↑（受后台干扰）|
| PSI memory some avg10 | 0.00 | 0.18 | 微升（回收活动）|

### A3. 判定 [推断]
- 内存侧方向明确正面：空闲页 6 倍、MemFree +550 MB、inactive_anon 减半 —— 符合 MGLRU 更积极回收冷页并换出
- PSI cpu / loadavg 上升**不能归因于 MGLRU**：观察期仅 120s、开机仅 3h、后台进程 12107→12198 仍在初始化，属负载波动
- pgmajfault +8.4% 是「更积极换出→回页」的预期代价，量级可接受
- **建议：保持 0x0003 观察，随时 `echo 0 > .../enabled` 回滚**

## B. KMI / vermagic 矛盾解析（修正 b069886）

### B1. 核心数据 [事实]
- UTS_RELEASE = `5.15.178-android13-8-g362d545d31a5`（内核，构建 2024-12-01）
- `/vendor_dlkm/lib/modules` 共 **293 个 .ko**，vermagic **全部 = `5.15.78`**
- `/system_dlkm/lib/modules` = 0 个 .ko
- `/proc/modules` = **406 行**（全部加载成功）
- `CONFIG_MODVERSIONS=y`、`CONFIG_MODULE_SIG=y`、`CONFIG_MODULE_SIG_PROTECT=y`、`MODULE_SIG_FORCE` 未开

### B2. 结论 [推断，多证据交叉]
1. **406 个模块全部成功加载 = 符号 CRC 完全匹配**。在 MODVERSIONS=y 下，加载判据是符号 CRC，而非 vermagic 字符串
2. `5.15.78` 是 **vendor 模块 vermagic（小米 vendor KMI 版本号）**，与内核 UTS `5.15.178` 并存是 Android GKI 正常现象，**不是故障**
3. 406 - 293 = **113 个模块来自 boot/initramfs 内嵌的 GKI 模块**，印证 boot_a 内核 + vendor_dlkm 模块体系完整自洽
4. 内核构建 2024-12-01 早于 ROM 发布 2026-04-03 属正常（内核先冻结，ROM 层后迭代）

### B3. 对 b069886 的修正
- ~~"boot_a 与 ROM 非同源"~~ → **推翻**：boot_a 的 5.15.178 内核就是本 ROM 同源 stock 内核
- ~~"vermagic 矛盾未解决，任何自编内核须先解决 KMI"~~ → **修正**：vermagic 差异是 vendor KMI 版本机制，非障碍；真正要保证的是「新内核导出符号 CRC 与 293 个 vendor 模块一致」
- **关键结论 [推断]：重编内核可行**，前置条件 = 拿到小米官方 `Module.symvers`（或从现网 vendor 模块反推 CRC）+ 同一 clang 14.0.7 (r450784e) + LLD 14.0.7

### B4. 新发现：MODULE_SIG_PROTECT=y [事实]
- 之前仅看 `MODULE_SIG_FORCE` 未开即判定「自编模块可加载」，但 `MODULE_SIG_PROTECT=y` 是 Android 特有保护，签名校验失败时可能拒绝加载
- [未确认] 需实测 `insmod` 一个良性模块才能确认自编模块是否真能加载
